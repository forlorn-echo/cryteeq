## 1. Scope of 1.0.0

1.0.0 comprises exactly the frozen specs `v-0.0-base` through `v-0.7-health-check` plus the contract-neutral packaging work that made the README quick start reliable (self-bootstrapping `prepare`, pack-based global install):

- **Review loop** (`v-0.0`, `v-0.2`, `v-0.5`): PR-style line-by-line commenting on any UTF-8 text file; instant, resumable SQLite-backed comments; Start Fresh; Complete Review with rendered report dialog
- **Deterministic report + agent contract** (`v-0.0`, `v-0.3`): Markdown report on `--stdout` with verbatim line/range quotes; format and parsing rules normative in `SKILL.md`
- **Themes** (`v-0.1`): Catppuccin / Dark / Light, persisted per reviewer
- **Range quotes** (`v-0.3`): contiguous line-range selection, `## Lines N-M` sections
- **Page title** (`v-0.4`), **`--start-fresh`** (`v-0.6`), **page-close health check** (`v-0.7`: all tabs closed → exit `130`, comments saved)

## 2. Versioning Amendment (normative)

| ID | Requirement |
|----|-------------|
| VR-1.1 | `package.json` becomes `1.0.0` on completion of this spec |
| VR-1.2 | Post-1.0 behavior changes append `specs/v-1.<n>-<topic>.md` (monotonic `n`; the first is `v-1.1-<topic>.md`) and ship as `1.<n>.0`; the patch digit remains for contract-neutral fixes. Frozen `v-0.x` specs are never renamed or renumbered |
| VR-1.3 | `--version` keeps reading `package.json` at runtime — no version is hardcoded in source or docs |

- Binary release assets, npm-registry publication, or install-flow changes
