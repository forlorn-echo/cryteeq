## 1. User Story & Expected Behavior

**As a human reviewer**, when the review UI opens, my browser tab immediately reads `cryteeq-ing…`; as soon as the review metadata loads, the tab reads `cryteeq-ing <file_name>` (e.g. `cryteeq-ing notes.md`). The title stays that way for the whole session — theme switches, restarts, and the completion dialog do not change it — and falls back to `cryteeq-ing…` whenever the review metadata is unavailable (loading skeleton, error screen).

The contracts in §2–§5 are **normative**. Nothing in this spec modifies the CLI, exit codes, stdout purity, the report format, the API, or the database. `SKILL.md` is unchanged.

## 2. Functional Requirements

### 2.1 Page title (FR-9)

| ID | Requirement |
|----|-------------|
| FR-9.1 | The document (browser tab) title is `cryteeq-ing <file_name>`, where `<file_name>` is the reviewed file's basename (`ReviewMeta.file_name`). The client sets it once the review metadata resolves; it remains unchanged on the completion (report) screen and across theme switches. A restart re-fetches the metadata for the same file, leaving the title unchanged |
| FR-9.2 | Before the metadata resolves — initial load before hydration, the loading skeleton, and the error screen — the tab shows the static placeholder `cryteeq-ing…` declared in `index.html`. The placeholder is also the restored value if the metadata becomes unavailable |

## 3. Non-Functional Requirements

| ID | Requirement |
|---|---|
| NFR-10 | The title is a client-side DOM effect only; no server, API, DB, or build changes. No `console.*` calls. The effect runs unconditionally before any early-return render branches (hooks rules) so loading/error screens are covered |

## 4. Interface & Data Contracts

### 4.1 CLI — unchanged

No new flags; `SKILL.md` is not modified by this spec.

### 4.2 Client contract

- `index.html`: `<title>cryteeq-ing…</title>` (static, covers pre-hydration).
- `src/client/App.tsx`: a `document.title` effect placed alongside the existing `data-theme` effect, before the loading/error early-returns:

```tsx
useEffect(() => {
  document.title = review.review
    ? `cryteeq-ing ${review.review.file_name}`
    : "cryteeq-ing…";
}, [review.review]);
```

- All other components are untouched; the title is never rendered in-page (the header continues to show the file name itself).

## 5. Out of Scope (do not build)

- Path or directory in the title; per-screen titles (e.g. a different title on the completion dialog)
- Server-side title templating (the SPA is served statically)
- Persisting or configuring the title format
